# The drain ends with a summary node, one agent, either runner

After `review` the drain runs a `summary` node: one agent, `script: summary`, `depends_on: [review]`, timeout 2000000ms. It is the only place the three reviews are merged: open with what the range does, then the findings that survive (deduped, ranked, file and line), then the reviewers' disagreements with its own call, then what it dropped or demoted and why, then one line per section that is an error rather than a review. It may add no finding of its own - it ranks and merges, it does not review - and it stays under 600 words. Bun writes `$ARTIFACTS_DIR/summary.md` from the agent's own final message, session log as fallback.

Same tools and same contract as a reviewer: handed `review-base`...HEAD, the `git log --oneline` menu and the reviews themselves, it may read `git log`/`git diff`/`git show`/`cat`/`rg` and has no writes, no commits, no spawned agents. Same switch as every other agent node: `runner: pi | dsh` in `<Target>/.scratch/ticket-dag.yaml`, overridable per run with `archon workflow run --input config=<path>`. One key, four agent nodes (implement, conflict, review, summary); `AgentRole` gained `summary` for its session file.

The node is skippable, and says so: no `review-base`, an empty one, no `review.md`, an empty one, or a `review.md` that is itself a `skip:`/`review error:` line writes `skip: ...` and spends no agent. An unreadable HEAD writes `summary error: git rev-parse ...`; a thrown runner writes `summary error: ...`. Nothing reads `summary.md`: like `review.md` it is for the human, not for settle, and the node exit is 0 either way.

Rejected: three per-axis summaries (the axis split is what the merge exists to undo); a summary that may introduce its own findings (a fourth opinion on the same diff); gating the drain or a ticket Status on the summary; writing the summary over `review.md` (the raw reviews stay readable); a shorter wall clock than a reviewer's (a summary that is visibly worse than its inputs is not worth the agent); a separate `--input runner`, because per-node runners would make one drain two configurations to reason about.
