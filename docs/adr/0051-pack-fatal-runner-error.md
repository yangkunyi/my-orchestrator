# A runner that cannot start is not this Ticket's failure

`RunnerUnavailable` (agent.ts) is the seam's type for "the turn never ran": no credentials, no persona, a model the SDK cannot resolve, a dsh that cannot spawn. A returned `PackAgentResult` stays a statement about a turn — a timeout or an aborted turn fails that one Ticket. `dsh-runtime.ts` gained `hasStarted()` so a pre-handshake failure (the binary is not there) is told apart from a post-handshake one.

implement and conflict record the reason through `failTicket` and rethrow, so the node exits non-zero instead of reporting a Git-contract outcome. Stopping the run then takes two things, and only one of them is the throw: the exit-code rule of ADR-0032 (a Git-contract outcome exits 0, a throw does not), and the drain's fan-out declaring `join: all_success`. That second half was measured with a real two-instance probe: under `all_done` a failed instance is only an `archon_failed` marker in the composed node's output, the healthy sibling still completes, and the run is reported as **successful**; under `all_success` the composed node fails and the workflow is reported failed. A failed body node fails the loop_group immediately, so no later iteration picks more Tickets — which is why the join is load-bearing rather than cosmetic.

The aborted Ticket is stamped FAILED with the config reason deliberately. Leaving it RUNNING would make the next drain's `rematchLeftovers` turn it FAILED *and* add it to that run's attempted set, so the operator's rerun would lose the ticket silently; and the git contract has no RUNNING→READY edge (pick stamps BLOCKED→READY only). FAILED is startable again, ignored by rematch, and its Worktree is reused, so a rerun after fixing the config retries it.

Measured ceiling: pick hands the loop up to `concurrency` Tickets at once and the probe showed the healthy sibling completing alongside the failing one, so one fatal error can touch a batch (four by default) rather than exactly one. The drain stops after that batch, the reason is recorded for every Ticket it touched, and the rest of the backlog stays READY. Report nodes still catch everything and write `review error: <msg>`: their product is the message and they cannot burn a Ticket.

Rejected: treating every runner error as fatal (a turn-level failure must fail one Ticket); exiting 0 on a configuration error (Archon would read a broken config as success); `join: all_done` on the drain's fan-out (a failed instance would be a marker and the run would report a config failure as success — measured, and now pinned by a test); resetting the Ticket to READY (no such edge in the contract this pack reimplements); leaving it RUNNING (a rerun would silently skip it); a pre-flight node in the drain graph (the adapters' checks are the honest ones, and the batch ceiling is smaller than a new node's cost).
