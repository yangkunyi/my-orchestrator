# The drain-end artifacts and the review axes each have one owner

`review-artifacts.ts` owns everything about the drain-end artifacts: the three relative names (`review-base`, `review.md`, `summary.md`), the `skip:`/`review error:` protocol (`skipLine`, `reviewErrorText`, `reviewErrorLine`, and the single reader `reviewSkipReason`), `writeArtifact`, and `writeReviewBase`/`readReviewBase`. `rematch.ts` writes the base through this module at the start of the drain, the reviewer and the summarizer read it back through the same one, and the summary's skip decision is that one reader's. The empty-drain case is the same protocol at both ends: an empty range writes `skip: empty diff <base>...HEAD, skipped`, so the summary node spends no agent on a non-review, and a test pairs the real producer with the real consumer.

`prompt.ts` owns the review axes: `REVIEW_AXES` as the list of titles, plus `reviewAxes()` and `axisHeading(axis)`. The fan-out, the per-axis session keys (`drain-review-<n>`), the `## <n>. <title>` headings and the summary's wording all read that one source, so adding an axis title alone adds a reviewer, its session and its section.

Rejected: letting `rematch.ts` import `writeReviewBase` from the reviewer (the base is the drain's artifact, not the reviewer's); each site writing its own heading string (that format is what a human reads; it belongs in one place); the summary counting "three" in prose (it reads `REVIEW_AXES.length`); a second skip-prefix spelling for the empty range (the P1 this review found: the producer wrote `empty diff ...` while the consumer looked for `skip:`).
