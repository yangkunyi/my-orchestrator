# The runner seam hands over one answer, and only what both runners honour

Every agent node reads its turn's product from one value: `PackAgentResult.answer`, a tagged `PackAnswer` - `{kind: "text", text}`, or `{kind: "none"}`. A runner reads its own product and reports what it found: Pi reads back the session jsonl it just wrote (`readPiSession` in `session-log.ts`, Pi's private reader), dsh takes the last assistant message out of its own event stream (`DshRuntime.lastMessage`), and both hand their text to `packAnswer`. Blank text is `{kind: "none"}`, the same as no text at all; the bytes of a real answer pass through untouched. Every node then makes one decision in one place: `report-node.ts`'s chain is `kind === "text" ? text : lastError ?? fallback`.

`sessionFile` stays on the result as diagnostics for the human reading a run, never as a way to obtain the answer. `PackAgentOpts` carries what a runner needs and nothing a runner cannot keep: `cwd`, `artifactsDir`, `sessionKey`, `role`, `model`, `thinkingLevel`, `runner`, `persona`, `prompt`, `wallMs`, with `persona` required. `artifactsDir` and `sessionKey` are Pi-shaped by nature - they say where Pi keeps its session jsonl, while dsh keeps its own log under `DSH_HOME` and reports that path back - so they stay on the seam as "where this session lives" and never as a way to get the answer. What left the seam is what one runner could not honour: a tools allowlist and a bash flag. A part is the answer only when its own `type` says `text`: dsh's `answerText` skips `reasoning` parts (they carry a `text` key, which is how thinking once leaked into a report), and Pi's `contentText` now applies the same test - measured over 344 real Pi session files, every part carrying a text key already had `type: "text"`, so the tightening is byte-neutral for Pi.

Rejected: an optional answer (a runner that reports nothing pushes its node back to re-parsing a session log, and only Pi's log has a parser - which is what the seam was quietly carrying); `sessionFile` as the answer channel (a log is diagnostics); `tools`/`useBash` on the seam (dsh cannot honour them: its minimal tree exposes one bash tool and no allowlist, so the option was a promise one runner could not keep); a runner-specific "final text" helper in each node (three copies of one chain).
