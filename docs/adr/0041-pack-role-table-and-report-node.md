# A node declares a role, and a report node is one skeleton

`roles.ts` holds one `ROLES` table: per `AgentRole` (implement, conflict, review, summary) the session key, the persona builder, the tools allowlist, whether bash is needed, and the wall clock. Nodes build their agent call through `roleAgent({role, args, cwd, artifactsDir, config, prompt})` instead of assembling a ten-field `PackAgentOpts` literal each, so the accidental option copying (a review node inheriting the ticket's wall clock or tool set) is no longer expressible. `AgentRole` is the one vocabulary: the same name is the node id, the script file, the session directory and the row in this table.

`report-node.ts` holds the other repeated shape. The two drain-end nodes are one skeleton: resolve the artifact path from the base, stop without spending an agent when the base or the artifact is missing or empty, `rev-parse HEAD`, the `git log --oneline` menu, the single agent call, the answer chain, the write. `runReportNode(node, target, opts)` owns those steps; `review.ts` (60 lines) and `summary.ts` (48) are the node definitions plus what only they know - three axes in parallel, and the merge rules. A fourth report node is a `ROLES` row and a node definition, not a fourth copy of six steps.

Rejected: per-node option literals (four copies of the same fields, drifting one card at a time); inheritance or a class hierarchy for the two report nodes (a function plus a record does the job and stays readable in a 60-line file); merging review and summary into one script behind a flag (different products: three parallel axes against one merge attempt); moving runner policy into `report-node.ts` (a role's shape belongs in the table, whichever skeleton runs it).
